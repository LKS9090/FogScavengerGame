# P01 人物与机器人小闭环交付

状态：2026-09-12 功能实现、独立构建与自动验收通过，交付用户试玩。不是正式美术或正式模型策略版本。

## 直接试玩

运行 `C:\Users\kanshan\FogScavengerGame\Builds\P01\FogScavenger.exe`。无需启动 Python 或 Unity 编辑器。分发时复制整个 P01 文件夹，不能只复制 exe。当前为普通 Windows 构建。

| 操作 | 效果 |
|---|---|
| WASD / 方向键 | 控制绿色玩家 |
| F 或左侧跟随按钮 | 蓝色机器人跟随 / 召回，替换之前的到点任务 |
| G 或左侧等待按钮 | 取消当前路径，机器人原地等待 |
| 鼠标右键点击地面 | 指定机器人独立前往的目标，黄色标记显示目标 |
| R | 重置人物、机器人、当前任务、速度与目标标记，开始新回合 |
| Esc | 退出独立程序 |

初始和重置后机器人处于等待状态。先按 F 开始跟随。地面之外或不合适的位置会显示目标不可达。点到墙面、人物或界面时不当作合法地面目标。

若 Windows 弹出网络权限窗口，本测试不需要入站网络权限，可手动取消；本次未自动操作系统安全窗口。由于该窗口遮挡，完整的鼠标点击与无遮挡画面人工验收还需用户试玩；中文面板能正常显示已观察到。

## 建议用三分钟检查

1. 按 F，带机器人绕到中间墙的另一侧。看机器人绕行及近距离停下是否自然。
2. 按 G 后走远，确认它留在原地；再按 F 召回。
3. 按右键指定墙另一侧地面，看黄色标记、前往和到达状态。前往途中按 G/F，确认旧任务被取消或替换。
4. 右键墙面/场外，检查不可达提示。移动中按 R，确认两者回到初始位置，机器人不会继续跑向旧目标。
5. 玩家靠近机器人时检查碰撞和通行感受。当前是宽阔灰盒，不代表任意狭窄门道都已验证。

## 实现了什么

- 机器人使用 Unity NavMeshAgent 和预先烘焙的可行走区域绕开静态墙体；AI Navigation 1.1.6。
- 等待、跟随、前往三个命令模式；到达、目标不可达及超过两秒无进展的受阻反馈。
- 跟随定期更新玩家目标，采用近距离停止和重新跟随阈值，减少原地抖动。
- 玩家带导航障碍体供机器人局部避让，保留人物与机器人的物理碰撞；场景加边界墙防止走出平台。
- 玩家按键移动仍由 CharacterController 执行。Robot 现在是脚底处的单位缩放根节点，原蓝色胶囊为 Body 子对象，视觉尺寸仍为高 1.2 米；这种结构让导航尺寸和模型缩放分开。
- 左侧中文操作面板，右侧固定斜俯视场景，蓝/绿角色与黄色目标标记。
- 每个会话写独立 JSONL，记录真实观察、命令、状态变化和回合边界。没有编造完成结果。

全部机器人行为是规则导航，本次没有新增神经网络训练，也没有把官方平衡球模型用于机器人。聊天、语音、道具、威胁、协作解谜和剧情尚未加入。

## 验收结果

最终普通 Windows 构建通过自动运行检查，详见 Reports/P01/acceptance.json：

- 人物实际移动并被中间墙阻挡；等待机器人不随按键移动。
- 机器人实际绕墙跟随，接近玩家后停止。
- 等待取消路径，到点后真实报告到达，无效目标拒绝。
- 通过把导航执行器速度临时设为零的受控故障注入，验证受阻提示；恢复速度后继续移动。此项不声称验证所有动态障碍情况。
- 召回替换尚未完成的到点任务。
- 十次连续重置：位置、命令编号、模式、路径、速度、玩家输入和目标标记全部清空；额外等待后旧任务不重新启动。
- Python 校验通过：实际会话包含 11 个重置边界（首次启动 + 10 次测试重置），事件顺序、回合时间、有限数值和重置状态一致。记录数见 Reports/P01/log-validation.json。

修复了角色控制器最小位移阈值在极高帧率下吞掉位移的问题、导航路径不能在 MonoBehaviour 字段初始化时创建的问题，并安排导航网格加载后才启用机器人 Agent。验收模式固定模拟时间步长；正常试玩不强制固定模拟步长。

## 日志与时间约定

运行日志位于 `%USERPROFILE%\AppData\LocalLow\LKS9090\FogScavenger P01\P01Logs`。

- schema=1；environment=p01-sandbox-v1；controller=rules-navmesh-v1。
- 坐标是 Unity 世界坐标，单位米，Y 向上；玩家位置是胶囊中心，机器人位置是脚底根节点，两者 Y 含义已明确。
- time 为本回合模拟秒数；tick 是 Update 计数，sequence 在本会话内连续递增。新回合 time/tick 清零。
- 常规观察约 5 Hz，命令与状态事件发生时立即记录。player_input 是二维方向；target/mode 是高层动作目标；desired_velocity 和 robot_velocity 分别是导航请求速度与实际速度，单位米/秒。
- 无外部服务依赖。当前是文件记录和 Python 校验，不是已实现 TCP、LLM 调度或训练接口。

校验自己的日志：

```powershell
conda activate fog-mlagents
cd C:\Users\kanshan\FogScavengerGame
python Training/validate_p01_log.py "实际日志文件路径"
```
