## 本轮协议 v1

机器可读规格在 `Training/switch-task-v1.json`，当前手工与 Python 实际接口一致。

| 项目 | 定义 |
|---|---|
| 任务 | 一个已知开关目标的局部接近、停止、持续保持 |
| 场地 | 12 × 12 米平地，边界墙；零或一个中央障碍 |
| 机器人 | 高 1.2 米、半径 0.35 米；最高速度 6.5 米/秒、加速度 18 米/秒²、转向 540 度/秒 |
| 物理步长 | 0.02 秒（模拟 50 Hz） |
| 决策周期 | 每 5 个物理步更新动作（模拟 10 Hz），其间重复上一动作 |
| 动作 | 2 个连续值：世界 X、Z 方向，分别限制到 [-1,1]，再限制向量长度不超过 1 |
| 开关激活 | 机器人脚底到开关中心的三维距离小于 0.72 米，与 P02 共用判定函数 |
| 成功 | 开关连续激活且实际水平速度不超过 0.15 米/秒，持续 3 秒 |
| 保持中断 | 离开开关或速度超过阈值，保持计时清零 |
| 超时 | 15 秒未完成，通过 ML-Agents EpisodeInterrupted 返回截断 |
| 异常 | 越界、非法数值动作分别结束并记录原因；作为环境/输入问题调查，不能全部算策略能力差 |
| 奖励 | 本步只设稀疏占位基线：成功 +1；越界/非法动作 -1；超时及中间步骤 0。奖励塑形在后续教师/训练步骤审查 |

三秒是训练测量窗口，不改变正式游戏“等待召回或满足明确协作条件”的行为。P02 的开关激活不要求停稳三秒；这是学习技能额外的稳定性验收条件。

## 28 维观察

| 索引 | 内容 |
|---|---|
| 0–2 | 目标相对 X/Y/Z，分别除以 12/3/12 后限制到 [-1,1] |
| 3–4 | 实际水平速度 X/Z，除以 6.5 |
| 5–6 | 上次实际应用的动作 X/Z |
| 7 | 是否压住开关，0 或 1 |
| 8 | 连续稳定保持秒数 / 3 |
| 9 | 回合模拟时间 / 15 |
| 10–11 | 移动执行器当前请求速度 X/Z / 6.5，用于明确加减速内部状态 |
| 12–27 | 16 条水平物理射线距离 / 8，无命中为 1；起点脚底上方 0.6 米，从世界 +Z 起每 22.5 度一条，检测墙/障碍层 |

动作和传感器使用世界坐标，与玩家相机旋转无关。手动输入先从屏幕方向转换到同一动作协议。没有 RGB 图像、全图障碍坐标、隐藏道具或玩家未来轨迹输入。

## 环境版本与数据

- 环境 `switch-local-v1`；执行器 `capsule-motor-v1`；行为名 `SwitchMotorV1`（Python 返回时带 team 后缀）。
- 配置 0–3 无中央障碍，4–19 有障碍，起点/目标随配置固定生成；0–15 是后续训练候选，16–19 预留。本次对全部配置做的是环境有效性检查，不是用预留配置调模型。
- 固定配置随机源 `31000 + configuration`；配置可通过 Python EnvironmentParameters 的 `configuration` 设置。
- 日志位置：`%USERPROFILE%\AppData\LocalLow\LKS9090\FogScavenger Switch Lab\SwitchLogs`，每会话独立 JSONL。
- 每 5 个物理步记录一次动作执行后的状态；终止和重置立即记录。数据含环境版本、配置、回合、序号、物理步、模拟时间、动作、28 维观察、位置/速度、保持、碰撞与结果。
- 明确 reset 日志时间为 0。Release 21 的 Python reset 首次返回观察有时已执行一个零动作物理步，因此时间允许为 0～0.02 秒，其他运动、动作和保持状态必须清零；这一点已实测。
- `last_outcome` 保留上回合结果供界面显示，不代表当前回合已结束，也不作为模型观察。

## 验证结果

最终交付程序通过两种独立检查：

1. Unity 环境检查：20 个固定配置按验收脚本提供的路径完成真实移动与三秒保持；墙体碰撞、射线、动作限幅、减速、保持中断、超时、越界、非法动作及十次重置通过。
2. Python 通信检查：实际连接 UnityEnvironment，收到 28 维观察与 2 维连续动作；零动作得到超时截断；发送移动动作得到真实成功终止及 +1；十次 Python 重置通过。

验收路径/无障碍比例控制只是测试驱动器，**不是已经完成的规则教师、训练示范集或模型成绩**。真实日志校验通过：1987 条记录，20 个配置，21 次成功事件，以及各一例超时、越界和非法动作。多次配置重建共记录 66 个回合起点。

共用开关判定与依赖调整后，P02 在验证副本中重新构建并运行原验收，结果通过；原 P02 场景几何与用户已有试玩程序未替换。

## 依赖与改动边界

接入此前实测的 Release 21：Unity ML-Agents 3.0.0-exp.1、Sentis 1.2.0-exp.2；Python 沿用 fog-mlagents，不更改 fog-gpu。

ML-Agents 以保留原始许可和全部内容的本地压缩包固定，避免克隆到其他电脑后引用本机训练目录。来源与 SHA256 见 `Packages/MLAgents-Provenance.md`。

模板中的未使用 UOS Launcher 与 ML-Agents/Sentis 引入重复 Protobuf 类型，产生 CS0433，已移除该包依赖；旧 UOSSettings 资产移动到 `Training/Compatibility/LegacyUOS` 保留，避免缺失脚本资产仍进入 Resources 构建。未修改账号或系统设置。

统一执行器使用 CharacterController，沿用 P02 导航机器人的尺寸和速度参数，但**不声称它与 NavMeshAgent 的碰撞/避让实现完全相同**。P02 继续使用规则导航；后续模型回接时必须在同一执行器下对照并重新试玩。这个训练场不含楼梯、动态玩家或长距离规划，它们是后续难度扩展。
